# PIKOL CHAR — Implementation Outcomes

- [x] **Project foundation, architecture and local persistence.** Use React.js with Vite, TypeScript, Tailwind CSS v4, Shadcn UI, Lucide React, React Router, React Hook Form with Zod, TanStack Table, date-fns and Recharts. Use a component-based architecture, reusable UI components, custom hooks, modular feature-based folders, type-safe interfaces/data models, centralized calculation utilities, and a clean separation of UI, business logic and data access. For the initial implementation, use local mock data and localStorage persistence. Structure the application so Supabase PostgreSQL can be integrated later without rewriting the UI or business logic. Store monetary values as integer centavos where practical and durations as integer minutes. Use stable IDs and proper relationships for Court (id, name, hourlyRate, status), CourtSession (id, courtId, sessionDate, startTime, endTime, totalHours, hourlyRate, totalRental, status, createdAt, updatedAt), Player (id, name, contactNumber, createdAt), SessionPlayer (id, sessionId, playerId, totalHoursPlayed, calculatedPayment, paymentStatus), PlayerTimeLog (id, sessionPlayerId, timeIn, timeOut, durationMinutes), Payment (id, sessionPlayerId, amount, paymentMethod, paymentDate, notes), and LiquidationReport (id, sessionId, totalRental, totalPlayerHours, totalAmountDue, totalCollected, remainingBalance, status, finalizedAt). Ensure `npm run dev` runs successfully, navigation is not broken, and TypeScript has no errors.

- [x] **Professional shell, navigation and responsive design system.** Create a polished, modern, minimalist, professional admin dashboard, not a generic AI dashboard. Use Inter, 14px body and navigation text, 13–14px table text, 24px page titles and 16–18px section titles; consistent spacing, strong hierarchy, neutral colors, subtle borders, flat surfaces, 6–8px radii and useful hover states/transitions. Use #1E293B primary, #FFFFFF background, #F8FAFC secondary background, #E2E8F0 border, #0F172A primary text, #64748B secondary text, #15803D success, #D97706 warning and #DC2626 error; use green sparingly for successful payments/completed sessions. Do not use gradients, glassmorphism, unnecessary shadows, oversized rounded cards, decorative illustrations, excessive colors, oversized icons, unnecessary animations or nonfunctional components. Create a desktop fixed ~240px white sidebar with subtle right border, Lucide outline icons, subtle-gray active item and small active indicator; make it collapsible on smaller screens. Header contains current page title, current date, notification icon and administrator profile dropdown, on white with subtle bottom border. Navigation includes Dashboard, Court Sessions, Players, Time Monitoring, Payment Monitoring, Reports and Settings. Desktop uses a fixed sidebar, full-width tables and multi-column statistics; tablet uses collapsible navigation, responsive grids and horizontally scrollable tables where needed; mobile uses drawer navigation, compact statistics, responsive forms, player cards or compact tables, accessible Time In/Time Out controls and no horizontal overflow in primary layouts. The mobile interface must feel intentionally designed, not simply shrink desktop.

- [x] **Reusable UI components, forms and interaction states.** Use Shadcn UI components wherever appropriate, including Button, Card, Input, Label, Select, Dialog, Sheet, Tabs, Table, Badge, Dropdown Menu, Alert Dialog, Calendar, Popover, Tooltip, Skeleton, Separator, Sonner Toast and Form. Create reusable AppSidebar, AppHeader, PageHeader, StatCard, DataTable, StatusBadge, SessionForm, PlayerForm, TimeTrackingTable, PaymentSummary, PaymentDialog and LiquidationReport; avoid duplicate UI implementations. Use clear form validation, confirmations for destructive actions, concise toasts, loading/empty/error states and graceful handling of calculation errors.

- [x] **Dashboard operations overview and analytics.** Display Total Court Sessions, Active Sessions, Total Registered Players, Total Collections, Outstanding Balances and Completed Sessions. Each statistics card includes a small descriptive label, prominent numeric value, small Lucide icon and optional relevant status indicator; avoid colorful card backgrounds. Add Recent Court Sessions table columns Session Date, Start Time, End Time, Court Rate, Total Rental, Number of Players, Status and Actions. Add a simple daily or weekly payment-collection chart using Recharts with minimal gridlines.

- [x] **Court and rental-session lifecycle.** Let an administrator create a session with Session Date, Court Name or Number, Court Rental Rate per Hour, Start Time, End Time and optional Notes. Automatically calculate Total Court Hours = End Time − Start Time and Total Rental = Total Court Hours × Court Hourly Rate; e.g. ₱200/hour, 3:00 PM–10:00 PM gives 7 hours and ₱1,400. Support Scheduled, Active, Completed and Cancelled statuses. Show a sessions table with Date, Court, Schedule, Duration, Hourly Rate, Total Rental, Players, Collection Status and Actions. Support View Session, Edit Session, Manage Players, Open Time Monitoring, View Payments and Finalize Session. Validate required fields and invalid time ranges.

- [x] **Session player registration and participant counts.** Register a player within a specific court session using Player Name, optional Contact Number and optional Notes. Automatically update the session's registered-player count whenever a player is added. Display Player Name, Session Date, Time In, Time Out, Total Hours Played, Payment Amount, Payment Status and Actions. Allow administrators to edit or remove players before session finalization; protect finalized records against accidental deletion.

- [x] **Player time-in/time-out monitoring.** For each player, Time In records the current time and changes status to Playing; Time Out records the current time, calculates playing duration and changes status to Finished. Display Player Name, Current Status, Time In, Time Out, Total Hours Played and compact, clearly labelled actions. Prevent duplicate active Time In records and Time Out without an active Time In. Allow administrators to edit incorrect time records. Support multiple playing intervals when a player leaves and returns; sum all valid intervals. Prevent overlapping intervals for the same player and validate each interval falls within the court session. Automatically refresh displayed playing duration.

- [x] **Proportional rental-charge calculation and financial rounding.** Distribute total court rental according to actual playing hours: Total Player-Hours = sum of players' playing durations; Shared Hourly Rate = Total Court Rental ÷ Total Player-Hours; Player Payment = Player Hours Played × Shared Hourly Rate. Whenever any playing duration changes, recalculate total player-hours, shared hourly rate, every player's payment, amounts due and outstanding balances, and refresh the payment table. Players with zero playing hours are not charged by default; never divide by zero; use precise decimal/cent-based financial calculations; round individual payments to two decimal places; distribute rounding differences deterministically so all individual charges sum to exactly the court rental amount when players have chargeable playing time. Keep calculation logic separate from UI components. Distinguish calculated charges from payments collected. Preserve payment transaction history when charges change. Prevent editing finalized session charges without an authorized adjustment.

- [x] **Payment collection, history and balance monitoring.** Show a payment table with Player Name, Hours Played, Amount Due, Amount Paid, Remaining Balance, Payment Status and Actions. Support Unpaid, Partially Paid and Paid. Let an administrator record a payment with amount received, method, optional payment notes and payment date; support Cash, GCash, Bank Transfer and Other. Allow viewing payment history. Correct payments through authorized adjustments while preserving history. Display Total Court Rental, Total Amount Due, Total Collected, Outstanding Balance, Number of Paid Players and Number of Unpaid Players. Calculate Remaining Balance = Total Amount Due − Total Collected, and update payment summaries immediately after a payment is recorded.

- [x] **Liquidation reports, historical browsing and PDF/print output.** Provide a complete per-session report containing Session Date, Court Name, Court Hourly Rate, Session Start Time, Session End Time, Total Court Hours, Total Court Rental, Number of Registered Players, Total Player-Hours, Shared Hourly Rate, Total Amount Due, Total Collected and Remaining Balance. Include an individual player breakdown with Player Name, Time In, Time Out, Total Hours Played, Calculated Payment, Amount Paid, Remaining Balance and Payment Status. Validate liquidation against Total Collected = Total Court Rental: if true display “Fully Liquidated”; otherwise display “Pending Collection” and the outstanding balance. Support View Report, Print Report, Export PDF, filter by date and view historical sessions. Use a clean, print-friendly report layout.

- [x] **General and payment settings.** Provide settings for System Name, Default Court Hourly Rate, Currency (Philippine Peso, PHP), Default Session Duration, Time Format and Date Format. Payment settings include Available Payment Methods, Payment Calculation Method and Rounding Rules. Use appropriate forms, switches and selects; persist settings locally.

- [x] **End-to-end integrity and session finalization.** Implement the workflow: administrator creates a court session; the system calculates rent; the administrator registers players; participant counts update; the administrator records each player's Time In and Time Out; the system calculates individual duration; totals player-hours; distributes rental costs proportionally; records player payments; updates collections and outstanding balances; generates a liquidation report; and the administrator finalizes the session after verification. Validate required inputs; prevent invalid time ranges, duplicate active player logs and overlapping time records; preserve historical payment records; prevent accidental deletion of finalized records; display confirmation dialogs for destructive actions; handle empty states and calculation errors gracefully; recalculate dependent values consistently; keep financial totals accurate.

- [x] **Automated unit coverage for business rules.** Include unit tests for court rental calculations, player playing-duration calculations, multiple time intervals, proportional payment distribution, financial rounding, partial payments, remaining balances and session finalization rules.
